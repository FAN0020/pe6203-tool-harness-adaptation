拟定恢复规则与公平性边界

固定条件：三方法共用原始任务、标签、模型和推理设置。先保持 agent 4096 tokens / 12 轮；任何调整都须统一并另立版本。

评分：原始 rubric 原文保留，只精简输出格式；先用开发材料验证。每条轨迹保留 5 个独立评分槽，每槽采用第一个有效结果，不能选最高分。JSON 有效不代表语义评分正确。

恢复上限：每个评分槽最多 2 次逻辑尝试，每次请求最多重试 1 次可恢复的连接/429/5xx 错误；五槽合计至多 20 次 HTTP 尝试。次数跨 resume 累计，耗尽仍记缺失。

断点：先保存提示、响应和 attempt ID 再前进。只恢复尚缺的评分，不重复已完成的 agent 或部署。连续两次请求重试后仍连接失败，暂停新工作；覆盖 agent、updater、judge。

副作用：被中断的工具调用不能盲目重发。已有部署 ID 时先核验原 URL；无法确认的副作用保留为中断，只有明确的已保存边界允许继续。

记账：保留每次尝试、原因、时间、已知费用与未知费用，分别列原始失败和恢复结果；预检、网页及诊断费用分开。

历史：新规则不追溯修改 A/B；低分不重跑，缺失单元不择优替换，三方法设置一致。

Full Rewrite 使用 LLM 重写全部描述，Selective Patch 用确定性差异规则复制受影响记录；比较同时包含范围与生成机制差异，不能宣称是纯更新范围消融。
