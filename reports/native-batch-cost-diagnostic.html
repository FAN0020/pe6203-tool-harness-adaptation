批量写入的收益取决于字段和依赖结构

冻结的三个结构、八条路径、69 次原生调用已完成，所有最终状态逐字段一致。默认平铺记录能省调用；完整字段的浅层计划不能省调用或依赖轮次；长链有取舍。本轮不调用模型，不计作开发通过、原 benchmark 成功或独立验证。Goal 仍未完成。

为什么需要这项诊断

上一版 native_record_batch 在原 283 Late 上未被采用，候选和 SP 的正常完成/产物全项通过均为 0/1。这个结果不能说明正确采用批量路线仍无效。此前 12 次原生准入只证明短段落可以一次保存多个记录，没有检验补齐字段和依赖后的完整成本。

此次定向核算上轮两份既有调用：候选 29 条、SP 47 条记录都显式填写优先级、复杂度、工时和标签；原生 parse_prd 不能原样指定这些字段，且初始没有层级/依赖。候选 28/29、SP 37/47 的文本可以形成 ≤500 字符的 ASCII 段落；没有超出 500 UTF-16 单元的段落。不能把未采用解释为所有文本都不适合导入，也不能从这些观察读出模型的选择动机。投影不进入任何更新器。

机制依据及冻结条件

复用 EasyTool 2401.06201v3 的调用验证思路和作者仓库 SHA 7624cf388b47334ff8a0868e7d862dde18cfda86，关键实现仍为 data_process.py:29、toolbench.py:140。本轮是项目自身对完整操作成本的诊断，不是原作者 actor 的复现。原生解析器哈希 d84ed2420bd56f9c648fe6a730fa61b9a12a3ab01254acbad86b5626859c338d，其余创建、更新、存储、列表源码也在冻结协议中固定。

68493fe 在调用前冻结三组独立合成输入（900301–900303）、顺序、字段验收、两种普通路径与批量路径、失败处理和零模型费用 ledger。模型、供应商、预算、actor、原生工具和原 benchmark 规则均未改。课程允许工具知识适应；严格双提升及两批验证仍来自用户要求，诊断不降低该门槛。

  • 普通直接创建：按依赖顺序创建，已知 parent/dependency ID 在创建时填写。
  • 普通延后补链接：先创建全部记录，使用创建收据返回的 ID，再集中补层级/依赖。
  • 批量导入：一次导入正文，列表取得 ID；完整字段情形再逐条恢复标量字段和链接，不重发已保存名称/正文。

后续调用的 ID 全部从原生收据或列表提取，磁盘状态仅用于评测。逐字段核对完整正文、名称、优先级、复杂度、工时、标签、状态、完成标志、层级和依赖；只排除随机 ID、时间戳。没有为了省调用删减产物要求。

实际结果

固定结构普通直接：调用 / 依赖轮次普通延后：调用 / 依赖轮次批量：调用 / 依赖轮次最终状态
900301：3 条默认兼容平铺记录5 / 3与直接路径相同，未重复3 / 3全部一致
900302：6 条完整字段、浅层树8 / 412 / 410 / 5全部一致
900303：6 条完整字段、依赖长链8 / 813 / 410 / 5全部一致

轮次是每种指定算法的依赖下界，不是实际模型轮次。它假定独立调用可放进同一回复，没有检验 4096 token 是否容纳这些参数，也未搜索所有混合算法。原生运行耗时和 UTF-8 字节数不能代替模型 token/推理预算；原请求字节数还包含工作目录名长度。

完整字段情形下，普通直接路径需 N+2 次调用，批量需 N+4 次：批量写入省去的逐条创建，被逐条字段恢复抵消，并增加一次导入和取 ID 列表。长链中，批量相对直接路径少三个依赖轮次，却相对延后补链接多一个轮次。不存在本测试范围内统一占优的批量路线。

决定与结论边界

不再优先修改上一版批量提示的措辞、位置或名称。“一次写多条”不能直接推出“完整任务更省预算”，这次测量改变了后续优化的依据。未观察模型采用、推理分配或最终质量，不能宣称已找到上轮不采用或截断的根因。

另一个方向是按字段判断是否保留旧知识，而非整条记录覆盖。盲目恢复全部旧描述已有反证：Early list_tasks 宣称可跨项目浏览，但原生要求 projectId；旧 sequentialthinking 也含不成立的保证。这些事实只排除无校验的整体回退，不否定逐字段、经源码检查的保留机制。它尚未形成下一项冻结候选，不因未证有效而要求额外审批。

下一机制仍须在现有信息边界内，改变真实知识决策并能被公平检验。没有把本诊断当作成功策略，也没有宣布合法方法空间穷尽。两批独立验证未启动。
