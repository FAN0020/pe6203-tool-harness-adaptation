3. Three adaptation strategies: 30 seconds

No Update retains Early knowledge. Full Rewrite rebuilds records and rewrites descriptions. Selective Patch updates affected records. Same execution agent; scope and generation mechanism both differ.

4. Selective Patch architecture

55 seconds

55 seconds. The harness contains names, schemas, descriptions, rules, output schemas and routing. We compare Early knowledge with target metadata. A deterministic diff detects additions, removals and field changes. An explicit reference index expands affected knowledge through one-hop dependencies. The implementation copies authoritative target fields for affected records and preserves unaffected knowledge. It retains valid usage rules instead of silently erasing them. Validation checks schemas, routing and preservation. The evaluated method makes no model calls during updating. The same agent then selects tools and arguments from the frozen snapshot and interacts with real MCP servers. Raw traces and five judge ratings are stored. No Update retains K0; Full Rewrite rebuilds target records and regenerates all descriptions using the fixed model. This compares update scope and generation mechanism together, not a pure scope ablation. Early uses K0 for all methods.

5. Experimental setup and fairness

50 seconds

50 seconds. Our documented subset contains task133 for mathematical syntax and security advice, task283 for project decomposition, and task235 for unchanged sales visualization. The first two represent parameter, description and relevant tool additions; the last measures retention. Three stages and three methods give27 cells, with one execution each. The brief permits one under compute constraints. Every cell receives five judge ratings, which are not five agent executions. We freeze DeepSeek v4.1 Flash through OpenRouter, temperature zero,4096 output tokens,12 rounds and the same judge rubric and recovery policy. Tool additions are optional paths; required renaming and removal are not tested. We make no full-leaderboard or unseen-task-family claim.

Selective Patch leads PE at9.1111, compared with7.8667 for No Update and8.3556 for Full Rewrite. It does not lead task fulfillment or cross-version ECS. 8. Recovery and retention

55 seconds

55 seconds. On changed tasks133 and283, the Selective Patch mean TF difference against same-stage No Update is zero in Middle and plus0.1 in Late. The gain is small because No Update can learn from runtime error messages and recover, and TF is near its ceiling. A direct mechanism is visible on task133 Late: No Update initially omits mandatory allow_variables and its calls are rejected, while Patch supplies it. On the unchanged chart task235, all strategies retain TF10. Patch has PE10 at every stage. No Update Middle nevertheless repeats map generation and gets PE4.8 despite unchanged knowledge. Thus unchanged knowledge does not ensure identical execution. These results support narrow observations, not broad adaptation or no-regression guarantees.

10. Under-update: what is actually confirmed?

60 seconds

60 seconds. The strongest stale-knowledge case is task133 Late No Update. The Early schema requires only expression. The Late schema also requires allow_variables. Four initial calls omit it and are rejected. Error feedback prompts the agent to repair its later calls. The final score is TF9.8 and PE7.2 after38 calls. This confirms a local stale-schema failure but is not a Selective Patch under-update. The corresponding Patch knowledge includes the parameter and all three validation calls supply it, with no tool errors. Our corpus screen found no missed metadata field in the original Patch records that had complete comparison data. This does not prove no semantic rule can ever be missed. The strict natural Patch under-update example remains absent.

11. Over-update: candidates and a negative diagnostic

75 seconds

75 seconds. We keep three distinct pieces of evidence. First, an older Full Rewrite chart trajectory edits all descriptions on an unchanged environment and scores TF8.8 and PE4.2. That is a suggestive regression, not proof of causality and not the main Patch method. Second, six later description rollback versus rewrite executions all score10/10 and complete. That negative result does not confirm the historical harm. Third, a linked-notes research variant appends a rule to metadata-unchanged evaluate and subsequently makes three extra evaluation calls, scoring PE5 against PE10 for original Patch. But four records differ between those arms, and evaluate is related to the changed validator. We cannot call the note unrelated or causally harmful without isolation. None of these is a confirmed natural over-update failure of the main Selective Patch.

12. Limits of the evidence

35 seconds

35 seconds. The subset is small, and there is one execution per cell. Provider execution can vary even at temperature zero. Five ratings cannot substitute for independent execution repeats. Our ECS disadvantage is partly driven by an Early truncation under common K0, so it is not direct evidence of harmful updating. Judge scores also have factual blind spots: three diagnostic answers say the annual sum is24.4 million, although the supplied values sum to25.4 million, and all keep their10/10 ratings. We preserve the grades and report the errors. Upstream tool defects, network failures and agent budget exhaustion are kept separate from update failures.

13. Conclusions and delivery status

40 seconds

40 seconds. We have a fixed-model adaptation pipeline, both baselines, a complete27-cell scored benchmark and reproducible raw-evidence calculations. Patch shows a useful local parameter-update mechanism, retains the chart-task TF and has the highest PE in this cohort. It does not win TF, ECS or normal completion. The main lesson is to report quality, efficiency, stability, cost and completion separately. The remaining course gap is strict failure-case evidence, not a numerical improvement threshold. We stop open-ended optimization. Any diagnostic would need a specific hypothesis and explicit approval; no larger matrix or deployment is scheduled.

14. Appendix: ECS definition and sensitivity

Q&A appendix

Q&A. For each task, take the mean TF across Early, Middle and Late and subtract its standard deviation, then average across tasks. Population divides squared deviations by3; sample divides by2. Released code uses population, while the paper appendix shows sample. We report both. Patch task133 has9,10,10, which lowers its ECS; the other two tasks have10,10,10. Do not compute ECS from aggregate stage means.

15. Q&A: fairness, replication and judge scores

Q&A appendix

Five-minute Q&A preparation. Q: Why only three tasks and one run? A: The brief permits a documented subset and one run under compute constraints; limitations are explicit. Q: Why not use the108-run confirmation? A: It is retained separately; original three arms already have three repeats, but separately frozen rewrites and build protocol should not be silently pooled. Q: Does temperature zero remove variance? A: No, provider execution remains variable. Q: Why not correct judge scores? A: That would change the frozen evaluation after seeing outcomes. Manual factual review is a separate evidence layer.
