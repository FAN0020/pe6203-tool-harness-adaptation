Findings and their scope

Under-update mechanism: an injected omission produces eight calls without the newly required allow_variables parameter; all eight are rejected. The complete snapshot has zero such rejections. This confirms a local mechanism under controlled fault injection, not a natural failure of original Selective Patch.

Extra-rule comparison: retaining one historical evaluate rule coincides with more calls, lower PE and truncation. The rollback also has slightly lower TF. With one stochastic execution per arm, this is suggestive evidence, not proof of general harm or a superior strategy.

Total recorded API cost: $0.04600192. There are no unknown request charges in this cohort. Execution and judging took 160.707 seconds (2.68 minutes), excluding preparation, analysis and packaging. No updater-model calls were made.

All four approved trajectories are terminal. No repetitions, new candidates, Netlify deployment or larger matrix were started. ECS is not defined for this single-stage two-condition diagnostic.

U: missing parameter knowledge

Exact intervention

Task 133, Late. The control uses the exact archived main Selective Patch snapshot. The injected arm removes only parameters.properties.allow_variables and its entry in parameters.required for math-mcp::validate_syntax. All other knowledge and the live tool schema stay identical. This deliberately bypasses the original updater's correct output.

Observed failure and recovery

The first injected validation call uses 2 + 3 * (4 - 1) / 2 without allow_variables. The server returns: validate_syntax requires allow_variables to be explicitly provided as a boolean. All eight validation calls in rounds 1-3 omit the field and receive this rejection. The agent later switches to evaluate, makes 17 evaluation calls in total, and reaches the output limit.

The control supplies the field in both validation calls. Its five calls include a separate batch_evaluate call that returns an upstream implementation error: this.toolHandlers.handleBatchEvaluate is not a function. Its agent loop finishes normally.

Judge error and causal limit

Four control judge rationales incorrectly say batch_evaluate is outside the available tools. It appears in the knowledge, live metadata and model-facing tool list. The implementation does fail. Whether distinct validation/evaluation checks are redundant is also debatable. Every original rating remains unchanged.

Confirmed: absent arguments directly cause the eight local rejections. Not established: a natural Patch under-update, prevalence, or a PE benefit from the correction. PE is 0.2 lower in the control despite fewer errors and normal completion.
