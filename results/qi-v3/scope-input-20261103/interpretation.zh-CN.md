# V3 输入优化结果

V3 已改成程序优先：程序完成确定的元数据更新，先定位显式关联；LLM 轻量筛查剩余目录，补充隐含影响或不确定项；程序合并去重；LLM 对每个候选只做一次局部复核并提出修改。程序继续检查来源引用、字段保护、schema、路由和参数回归。

不再每批重复发送全目录索引，也不再同时发送旧版、新版、程序修改版三份记录。程序已完成且没有旧使用规则需要复核的条目，不再交给 LLM 重做。

V3 的能力证据层和可选 Python 隔离测试修正闭环保留；V2、No Update、Full Rewrite 和评测模型预算未改。使用 `--selective-mode hybrid_v3`，并检查产物中的 `updater_core_version=hybrid_v3_program_first_v1`，即可确认走的是本次优化版本。

前后使用同一模型与供应商，直接读取 API 回执。这16次真实更新请求共花费 USD 0.016608312，没有未知费用。脚本对照的四组知识输出完全一致。真实模型的表述不同，但本次有限样例中的元数据、无关规则、旧规则移除、单位转换表述和能力证据均已检查。

最初的检查器把“变更条目新增文档规则”以及“没有重复写100的分到元转换表述”误判为失败。原始结果和检查器均保留；修正后只读取原输出复核，没有重新调用模型挑结果。详见 offline-review.json 和英文 README。

回归检查为430项通过、9项跳过；13项原生MCP集成测试未运行。真实Docker有限测试和“失败反馈→修正→再次隔离测试”的公开入口验收通过。

另修复无变化场景的阶段标记：知识可以沿用Early K0，但更新产物的target_stage应指向实际要运行的Middle/Late，避免任务在启动前被拒。三阶段回归用例均验证零模型调用及规则保留。

这里验收的是更新阶段输入量和实现，执行阶段工具描述中的能力边界文本仍然保留。优化后的V3尚未重新跑任务TF/PE；不能把原有22/27条评分当成本次的新成绩，也不能用这些样例直接宣布整条任务更省钱。轻量筛查仍可能漏掉隐含关联，引用校验也不等于语义或安全证明。
