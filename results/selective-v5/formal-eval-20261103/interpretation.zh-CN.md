# 本轮正式评测结论

这轮只比较新版 V5 的知识更新与 No Update。两组使用同一执行模型、工具环境、轮数、输出预算和评审规则，都可以根据 MCP 错误反馈调整本次调用。没有额外的 Python 隔离测试或修正机会。V5 使用工具目录证据，没有加入独立源码或探针证据包。

任务为原版 MCPEvol-Bench 的 430（SwiftUI）、133（Python 数学运算安全建议）、90（游戏王卡牌与 LeetCode 每日题）和 235（销售图表）。每题 Early/Middle/Late，各组重复 3 次，共 72 条轨迹、360 个官方规则评分槽位。全部运行与评分完成，没有重跑挑选结果，没有未知费用。

每个任务环境的知识只更新一次，随后复用于三次独立执行，更新费没有重复记三遍。评审费另计 USD 0.181249860，不计入方法的任务成本。本轮实际总支出 USD 0.823440744。

V5 的平均评分更高、工具错误更少，本轮执行加更新的总费用高 6.13%。目前支持的说法是“以小幅费用增加换取部分任务更完整、调用更顺”，还不能说整体省钱。

## 哪些任务有收益

- **90-Late：改善最清楚。** TF 6.67→10，PE 5.20→9.60。No Update 的三次执行均未成功取得每日题，V5 三次都取得并在答案中给出与工具观察一致的题号、标题。两组都取得了卡牌资料和图片字节。计入一次更新的单次任务成本为 0.013824→0.016275 USD。No Update 的低费用伴随着缺少一项任务内容。
- **430-Late：调用更顺，但没有省钱。** PE 5.67→7.93，平均工具错误 2.67→0；平均调用次数 10.67→6.67。计入更新后单次费用 0.007984→0.009536 USD。较少的调用并不直接等于较少的输入 token 或更低账单。
- **133-Late：评分改善，更新开销较明显。** TF 8.60→9.73，PE 4.80→7.47；平均工具错误 5.67→1。计入更新后单次费用 0.007143→0.013332 USD。本轮没有执行生成的 Python 代码，不能据此判断代码安全或功能正确。
- **133-Middle：出现摊薄更新费的可能。** 平均执行费 0.008837→0.007283 USD；V5 更新费 0.002316 USD。按这三个样本的均值算，复用两次即可抵消更新费。但 PE 6.00→5.73，样本也少，不能直接当成稳定的部署阈值。
- **235：无需更新。** 三个阶段 V5 更新调用与费用都为零。两组的工具知识相同；18 条轨迹的三类图表数值与分组均匹配题目。这里只核对工具调用和返回的配置，没有验证最终网页渲染。

## token 与账单为什么不一定同向

90-Late 三次执行中，No Update 输入 417872 token，其中 206080 为缓存输入；V5 输入 263419 token，其中只有 10368 为缓存输入。V5 的输入总量少约 37%，但未缓存输入更多，因此本轮实际执行账单仍更高。原始 usage 与缓存统计保存在 receipts.jsonl 和 cache-readout.json。没有用推算价格覆盖真实账单。

## 结果能支持到哪里

这是一轮四题、每条件三次的正式小样本评测，不是全部 201 题结果。TF/PE 由模型评审；五次评分不能当成五次独立执行。“正常结束并输出回答”也不等于产物通过功能或安全测试。Early 与任务235的两组知识完全相同，仍出现评分与费用波动，说明单个小差异需要谨慎解释。

这轮比较的是完整的 V5 知识更新策略与冻结 K0。它没有单独测出 LLM 审查相对纯程序同步的增益，也没有检验源码/探针辅助路径或 Python 产物测试闭环。
