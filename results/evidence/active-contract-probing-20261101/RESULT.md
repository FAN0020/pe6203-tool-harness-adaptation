# 主动契约探针：生成实验及一次引用恢复，2026-11-01

结论：本版本未准入原 benchmark 开发，未进行两批验证；完整双提升 Goal 仍未完成。

## 证据到机制

此前原题开发反复出现持久化部分产物、却没有完整正确交付的现象。停止字段只能确认截断；它不能区分知识遗漏、构造能力和预算分配的原因。既有局部收益包括减少调用、改善部分 TF 或单个产物，但没有满足全部严格门槛。本轮只检验“更新器自主取得证据”这一缺口。

[ContDa 的正式论文](https://aclanthology.org/2026.findings-acl.1082/)与[作者源码](https://github.com/Bingo-W/ContDa/tree/e68497285587be3cb2022dbcdfb1ed244f50398b)固定至 SHA `e68497285587be3cb2022dbcdfb1ed244f50398b`。借鉴其模型生成查询、取得原生反馈、再调整描述的机制；位置为 `dynamic_evolution.py:100–253` 与 `LLM_client_discovery.py:61–119`。本轮没有复现其迭代收敛、嵌入检索、关系聚类或模拟 API。

与此前使用给定反馈的 LLM updater 不同，本轮 LLM 选择实际调用、问题和参数，再从真实返回值与合成持久化状态作字段决策。输入仅含旧/当前工具元数据和独立合成 fixture，没有 benchmark 问题、答案或已评分轨迹。只有实际变化/新增记录的描述字段可变；工具集合、结构 schema、路由、actor 和单次预算保持原冻结条件。课程要求、用户严格双提升要求与历史实现选择的区分沿用已有独立审查，未新增审查 agent。

## 核验与决定

9处操作事实经原生返回与源码核验得到支持，但有明确证据限度：`detailed` 的比较不能单靠一个 true 探针；项目第三个探针使用新 fixture，不能验证第一个探针创建的项目状态。

前例核查发现8处事实已在先前 actor 知识中出现：数学标志未生效、批量处理器缺失、项目状态工具失败，以及 repoUrl/tags 写入描述。第9处补充了非空项目时 `review_workspace_health` 先遇到缺失存储方法的条件；旧空工作区证据是另一个错误。不能把它们统称为全新知识，也不能把全部最终字节或组合称为已逐字测试过。

决定性准入失败是 `math-late C007`：生成字段复制了实际探针表达式 `((1+2))`。模型前冻结的生成规则明确不允许把探针常量/示例写入知识。本轮要求整包通过，不能手工删例或只选通过项继续。这是**本版本的表示约束**，不是用户永久禁止所有例子，更不是发现 benchmark 答案泄漏。该约束没有被升级为整个研究方向的禁区。

本轮支持“LLM 可自行选择实际证据并形成多数有依据的局部决策”，不支持正常完成率、实际质量、TF 或保持能力改善。没有 actor/judge 调用，也没有通过开发门槛。该具体版本关闭，不追加修复或重复采样。下一项有价值的机制检验需区分：自主探针能否发现与完整产物构造有关、且未被既有规则覆盖的关系；本轮尚未提供这样的已准入候选。
