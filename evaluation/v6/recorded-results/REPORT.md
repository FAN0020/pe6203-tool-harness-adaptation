# selective-V6：开发与正式 Evol 记录

V6 已实现，并完成先离线、再单格试跑、最后其余条件的验收流程。正式批次为 r4，执行代码提交为 `8401df2a1d9356717394d3ab0d0a6920bcbce5dc`。r1–r3 是保留的开发诊断批次，不与 r4 混算成绩。

这次解决了 V5 的请求膨胀和部分更新无法发布的问题：9/9 条件更新成功，四个真正需要语义更新的条件全部通过。任务本身正常完成 7/9，平均 TF 9.156、PE 8.333；因此不能说 V6 的任务效果已全面超过对照组。

## 实际流程

完整工具资料留在本地 → 程序同步确定的元数据变化并清理失效引用 → 一次轻量全目录语义筛查 → 合并必查、潜在影响和不确定候选 → 只补候选及其依据变化需要的字段 → LLM 局部改 usage_rules → 程序验收 → 发布并冻结知识 → 执行任务，适用时验证并有限修复生成代码 → 事后诊断。

- 程序更新名称、参数 schema、描述、输出 schema、路由、增加和删除工具。LLM 可以引用这些事实判断语义影响，但不能改写这些字段。
- 全目录筛查只发用途、已有规则和变化摘要；不发完整 schema、源码或原始探针。程序保证工具 ID 覆盖完整，且模型不能删掉必查候选。ID 覆盖通过不等于已经证明所有隐含语义关系都被发现。
- 后续包只含候选及其引用变化对应的证据。字段按 JSON pointer 读取，内容池去重，相关候选可拆批；不携带全局目录，也不截断约束或丢弃候选。
- V6 的 updater 使用严格 JSON Schema 输出。程序继续检查真实 ID、证据范围和规则结构，不会自动补造模型引用，也没有放宽规则来接受先前失败的回答。
- 声明、源码片段和有限探针分别记录。证据不足写成未知或冲突；LLM 建议明确标为未验证，不写成运行保证。
- 独立探针使用此前冻结的、与任务答案无关的观测；本批次没有让模型临时生成探针。没有变化或可信异常时直接复用 K0。

流程图见 [selective-v6-flow.mmd](../../../docs/selective-v6-flow.mmd)，接口与边界见 [selective-v6.md](../../../docs/selective-v6.md)。

## 输入量与预算

正式上限在实际目录离线组包后冻结。一万 token 是首轮筛查的工程目标；输入预估采用 UTF-8 字节数 / 3 + 32，并计入 decoder JSON Schema，属于估算，不是 DeepSeek 的精确 tokenizer。

| 更新条件 | 首轮字符数 | 首轮估算输入 token | API 实际首轮输入 token | 整条更新字符数 | 更新调用数 |
|---|---:|---:|---:|---:|---:|
| 数学 Middle | 18,454 | 6,186 | 3,575 | 34,036 | 2 |
| 数学 Late | 21,179 | 7,095 | 4,209 | 61,950 | 3 |
| 项目 Middle | 19,060 | 6,386 | 3,582 | 42,921 | 2 |
| 项目 Late | 25,271 | 8,456 | 4,908 | 79,726 | 3 |

最大单次更新请求为 34,467 字符。四个环境更新合计 10 次请求、218,633 字符、48,954 个实际输入 token、15,078 个输出 token；这个累计量不能与 V5 单次 21.7–27.2 万字符混为一谈。正式 r4 没有发生更新修订或隐式重试。其余五个无变化且无可信异常的条件，更新 API 调用为零。

离线还把所有工具都当作候选进行了压力组包：四个更新条件的首轮及全部局部包累计 732,511 字符，无漏项、无截断。V5 旧实现重建的首轮审查包累计 7,459,600 字符；这两项是离线组包测量，不是额外实付调用或语义能力证明。

冻结上限：单条更新最多 32 次请求、900 秒、每包 120,000 字符、累计一百万估算输入 token、0.05 美元；每批候选一次补丁及最多一次补证据/修订。单格试跑上限 0.10 美元，全部 V6 开发和本次正式运行合计不超过 1 美元。每次新批次额度扣除了已发生的诊断费用。

执行和 judge 沿用此前同平台实验的 4096 输出 token、12 轮执行限制；updater 输出上限为 16384。4096 不是用户提出的新输入预算，也不是 MCPEvol 的硬性要求。V6 取消隐式 transport 重试与 judge 恢复重试，失败留档；原有基线未改动。

## 冻结、失败处理与验收

- 四个开发批次的独立代码测试文件、judge 源码、规则准入源码和声明的验收策略哈希一致，见 verification.json。没有为通过当前任务临时修改评分或测试。
- r1 因整字段证据选择器省略根 pointer 停止；r2 因跨工具依据引用不足停止；r3 因模型复制输入引用提示为多余输出字段停止。失败回答和原费用全部保留，未改判通过。修复针对组包/传输接口，未使用任务答案或 judge 分数生成知识。
- r4 用新的严格输出格式重新封存并重跑全部九格；先运行此前失败的数学 Late，试跑完成后才执行其余八格，不与 r1–r3 拼成绩。
- 每次任务执行前保存知识和验收协议哈希，运行后核对。实际结果与代码反馈只进入预先规定的一次代码修复，不能进入工具知识更新器。
- 事后诊断先检查冻结知识、保存的注入内容、实际调用与代码产物；区分知识问题、检索/注入问题、动作/代码问题、证据/验收不确定。它不改当前知识或测试、不自动重跑、不据 TF/PE 推断因果。保存的注入快照相等也不能证明模型真正理解并使用了它。
- 440 项测试通过，包含实际 Docker 的隔离、失败→修复→重测检查；另有 13 项 integration marker 测试未重复运行。9 格真实环境执行和 113 条实付请求另行核验，所有费用都能与原始 usage 对上。
